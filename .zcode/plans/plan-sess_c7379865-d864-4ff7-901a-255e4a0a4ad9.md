# AI Bureau — детальный план совершенствования + дорожная карта

## Что я выяснил (краткое обоснование)

За полированными маркетинговыми `.md` скрывается прототип с реальными багами. Параллельно твоя инфраструктура `foundation/skills/` уже содержит готовые ассеты (smart-rag на sentence-transformers+ChromaDB, sitemap-audit), которые ai-bureau не использует, дублируя их наивными JS-копиями. Структура монорепо расходится с задуманной чистой моделью (25+ проектов в корне вместо `projects/`, пустой `templates/project-skeleton/`, дублирование скиллов между `foundation/` и `~/.agents/`, два разных ai-bureau).

Решения, принятые с тобой:
- **Стек сайта → Astro** (моя рекомендация, обоснование в Спринте 2)
- **Хранилище лидов → Telegram** (Bot API → закрытый канал/чат)
- **Старт → Спринт 1: критическое + лиды** (остальное — дорожная карта)

### Спринт 1 — Критическое + лиды 🔴 (реализуем сейчас)

Цель: сайт начинает **реально собирать лиды** за 1–2 сессии.

**1.1. Починить `index.html` (КРИТИЧНО)**
- Убрать задвоенные теги (`<<htmlhtml`, `<<headhead`, `<<metameta`, `<<titletitle>`, `<<scriptscript`, `<<linklink`, `<<divdiv` — 13 мест). Сейчас head/JSON-LD/метатеги не парсятся браузерами и поисковиками.
- Добавить недостающие SEO-теги: `<meta name="description">`, Open Graph (`og:title/og:description/og:image/og:url`), Twitter Card, `<link rel="canonical">`, `<link rel="icon">`.
- Убрать дублирование JSON-LD: сейчас 3 блока Organization (2 в HTML + 1 из `App.tsx:6-33`). Оставить один каноничный, добавить `FAQPage`/`Service` schema.

**1.2. Сохранение лидов → Telegram (главное бизнес-требование)**
- В `server.js` добавить endpoint `/api/lead` (или расширить `/api/chat`), который при `stage === 'completed'` отправляет собранный лид (`businessType`, `task`, `budget`, `contact` + краткую AI-выжимку диалога) в Telegram через Bot API (`sendMessage` в `CHAT_ID`).
- Добавить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` в `.env.local`.
- Сейчас лиды **собираются и уничтожаются** — `server.js:53` игнорирует `context`/`leadData`, которые шлёт `useChat.ts`. Это прямая потеря каждого потенциального клиента.

**1.3. Память диалога + перестать выбрасывать AI-ответ**
- `useChat.ts:73-99` сейчас шлёт только последнее сообщение, получает `data.reply` и **выбрасывает его**, подставляя хардкод-заглушку. Решение: отправлять весь массив `messages` на сервер; сервер (`server.js:72`) передаёт его LLM; UI использует реальный ответ (с лёгкой «склейкой» с next-stage подсказкой, а не полной заменой).
- Эффект: бот перестанет переспрашивать то, что клиент уже сказал; ответ становится осмысленным, а не шаблонным.

**1.4. CSS-классы чат-виджета (КРИТИЧНО для UX)**
- `BureauBot.tsx` ссылается на ~9 классов, которых нет в `index.css`: `bot-progress`, `header-info`, `status-indicator`, `close-btn`, `step-dot`, `step-label`, `trigger-pulse`, `typing`, `msg-content`. Чат сейчас полураздетый.
- Дописать недостающие стили в духе текущей тёмно-циан-эстетики. Исправить конфликт: класс `.dot` сейчас по ошибке использует анимацию логотипа (typing-индикатор выглядит неправильно).

**1.5. Безопасность / хардкоды**
- Заменить `http://localhost:3001/api/chat` (`useChat.ts:73`) на env-driven URL (`VITE_API_URL` с дефолтом), чтобы работало в проде.
- Валидация `message` в `server.js`, проверка `data.error` от OpenRouter (сейчас падает с непонятной ошибкой). Заглушка rate-limit (минимальная).
- Починить парсинг `.env.local` (`server.js:8-11`) — наивный `split("=")` ломается на значениях с `=`.

**1.6. Консолидация ingest-скриптов**
- Удалить `ingest.cjs` и `ingest.ts` (используют Gemini 768-dim — **при запуске сломают сервер**, которому нужны OpenRouter 1536-dim). Оставить каноничный `ingest.js`. Добавить `npm run ingest` в `package.json`.

### Спринт 2 — GEO/SEO-фундамент + миграция на Astro 🟡

**Почему Astro (моя рекомендация):** SPA отдаёт пустой `<div id="root">` — краулеры Яндекс Нейро/Google AI Overview не видят контент. Astro рендерит статический HTML при сборке (краулеры сразу видят текст), а React-компонент `BureauBot` подключается как «остров» только там, где нужна интерактивность. Это принципиально для цели «быть в ответе нейросети». Next.js тяжелее для статичной витрины; чистый React SPA требует отдельного pre-render-плагина.

- Миграция `src/App.tsx` → Astro-страницы; `BureauBot` как `client:load` React-остров.
- Создать `public/robots.txt`, `public/sitemap.xml` (+ генератор в build), перенести `llms.txt` из корня репо в `public/` (сейчас не сервится). В качестве in-house эталона чистого SEO-стека использовать `projects/ai-eggs/vezem/public/{robots.txt,sitemap.xml,llms.txt}`.
- Добавить favicon (сейчас `public/logo.png` — 0 байт), реальный OG-image.
- Мультистраничность: `/services/*` (по одной странице на услугу), `/cases` (кейсы), `/blog`, `/faq`, `/privacy`. Каждая страница услуги = ответ на конкретный запрос + FAQPage schema (как требует `MARKETING_ROADMAP.md`).
- Подключить `foundation/skills/code/sitemap-audit` для самопроверки ai-bureau.pro (сейчас инструмент только аудирует чужие сайты вроде habr.com).

### Спринт 3 — Реальная реализация Smart Fallback 🟡

Сейчас `SMART_FALLBACK_STANDARD.md` — 100% маркетинг, **0% кода** (продаваемое «конкурентное преимущество» не существует). Реализовать:

- **Порог уверенности:** использовать cosine-`score` из `server.js` как confidence; при `score < 0.65` включать каскад.
- **Reframing:** отдельная ветка промпта — бот задаёт наводящий вопрос, предлагая термины из базы (вместо «не знаю»).
- **Гибридный поиск:** добавить keyword/BM25-компонент к векторному (`server.js:60-65` сейчас чистый cosine).
- **Seamless handoff:** при запросе человека — LLM-генерация summary диалога → отдельное Telegram-уведомление менеджеру с готовой выжимкой (логично ложится поверх Telegram-интеграции из Спринта 1).
- **Заменить базу знаний:** расширить `knowledge/raw/manual.txt` (сейчас 6 чанков-буклета) — добавить FAQ, кейсы, обработку возражений, процесс работы. Рассмотреть замену наивной JS-RAG на `foundation/skills/code/smart-rag` (sentence-transformers+ChromaDB, с recall-тестами).

- **Доделать content-factory:** сейчас `scripts/content-factory.js` — стаб, возвращает хардкод (коммент «Здесь будет вызов Gemini API»). Реализовать реальную генерацию статей для Дзен/VC + пагинация блога на сайте.
