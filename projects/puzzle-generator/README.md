# Puzzle Generator — Танцы в облаках (схема лазерного реза)

Генеративный пайплайн схемы пазла для лазерной резки по ТЗ «Танцы в облаках».
Создаёт SVG **450 деталей**, поле **310×430 мм**, чёрные контуры (рез) + голубые
прорисовки (гравировка) по сюжетным зонам.

## Требования ТЗ (выполнены)

| Требование | Значение | Проверка |
|---|---|---|
| Количество деталей | ~450 | ✅ 450 |
| Размер детали | ≤ 30 мм по большей стороне | ✅ max 16.6 мм |
| Зазор между деталями | ≥ 3 мм | ✅ min 3.00 мм |
| Контуры деталей | чёрные | ✅ |
| Прорисовки внутри деталей | голубые | ✅ 2359 путей |
| Толщина линий | 0.2 pt | ✅ |
| Формат | 310×430 мм, SVG (.ai открывается из SVG) | ✅ |

## Архитектура пайплайна

```
generate.py
  └─ build_grid(rng)     18×25 сетка с волнистыми гранями (амплитуда 0.45-0.8 мм)
       └─ each ячейка → Polygon.buffer(-1.5 мм)   → гарантированный зазор 3 мм
  └─ prim_*()            библиотека примитивов прорисовки (земля/солнце/небо)
  └─ pick_prims(zone)    выбор примитива по зоне детали (centroid)
  └─ export_svg()        чёрные замкнутые path + голубые лини, stroke-width 0.2
```

- **Детали** (чёрные контуры): сетка 18×25 → 450 замкнутых полигонов с
  волнистыми краями; соседи делят одну базовую грань, negative buffer −1.5 мм
  даёт равномерный зазор 3 мм.
- **Прорисовки** (голубые): по вертикальным зонам ТЗ —
  `земля (0-30%): волны/ели/дома/орнамент/снежинки`, `солнце (30-56%): коловрат,
  лучи, спирали`, `небо (56-100%): облака, птицы, танцоры, ленты`. Каждый
  примитив масштабируется ~0.3× размера детали и центрируется, не пересекая контур.
- Сюжетный акцент: самая нижняя центральная деталь получает «мужика с собакой»
  (отсылка к сказу «Девки в небе пляшут»).

## Использование

```bash
# генерация
./venv/bin/python3 generate.py --seed 7 -o "output/Танцы в облаках_310 x 430_450 дет.svg"

# верификация требований (+ сравнение с эталоном .ai→svg)
./venv/bin/python3 verify.py -s "output/Танцы в облаках_310 x 430_450 дет.svg" \
    -e /path/to/reference.svg --strict

# eval-набор
./venv/bin/python3 tests/eval_puzzle.py
```

Зависимости: `shapely`, `numpy`, `lxml` (в `venv/`).

## Художественный второй проход (PZL-4) — три параллельных трека

Результаты складываются в `exchange/` и сравниваются:

| Трек | Направление | Статус |
|---|---|---|
| **Код** | Расширение библиотеки примитивов (generate.py) | ✅ базовая версия, итерация при необходимости |
| **Recraft** (пользователь ищет API-ключ) | Recraft V3/V4 SVG рисует сюжетный слой → пайплайн режет на детали | ⏳ ждёт ключ; вход `exchange/recraft/` |
| **Дизайнер** | Правка голубого слоя прорисовок в Illustrator | ⏳ работает в `exchange/designer/` (BRIEF.md + SVG) |

Сравнение: художественное качество прорисовок (взглядом), соответствие ТЗ-сюжету,
чистота (прорисовки не пересекают чёрные контуры), инженерные метрики
(verify.py / eval) обязаны оставаться зелёными во всех треках.

- Формат сдачи дизайнера/Recraft: SVG с сохранённой разметкой;
  пайплайн применяет сетку деталей к присланному слою прорисовок.

## Inkscape CLI локально (трек MCP — закрыт как инструмент)

Реальный MCP-сервер `aravindev/inkscape_mcp` (PyPI `inkscape-mcp`, FastMCP) —
платформы **Linux | Windows**; на macOS требует pycairo/pygobject, которые не
собираются из исходников (проверено: `pycairo 1.29.1` / `pygobject 3.56.3` падают
на meson-сборке). Headless-режим MCP-сервера — просто вызов `inkscape --actions`,
поэтому эквивалент реализован локальным CLI-инструментом `tools/inkops.py`
(те же операции, без MCP-слоя и без pygobject):

```bash
./venv/bin/python3 tools/inkops.py --help
# render SVG→PNG (точное превью) | convert (.ai/.pdf)→SVG | to_pdf | trace (potrace)
./venv/bin/python3 tools/inkops.py convert "эталон.aravindev.ai" -o work/etalon_ink.svg
```

Проверено на эталоне «Танцы»: Inkscape 1.4.4 корректно декодирует `.ai` (PDF 1.5)
→ 3991 path, цвета #000000 / #29abe2 / #f15a24, толщина 0.2. Трейс цветных
референсов из ТЗ даёт рамки/кашу — для сюжетного слоя 1:1 не годится, художнику
нужен исходный рисунок, не автоповтор.
