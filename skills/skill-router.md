# Skill Router — ленивая загрузка скиллов по контексту

## Зачем

Hermes грузит скиллы **только по запросу** (skill_view), не preload'ит всё в
системный промпт. Это сохраняет prompt caching и не засоряет контекст.

Но агент должен **сам решать** какой скилл нужен — не гадать, не перебирать.
Этот скилл = карта всех доступных скиллов + правила выбора.

## Как использовать

1. Получил задачу от пользователя.
2. Пробежь по карте ниже — нашёлся релевантный скилл?
3. Да → `skill_view(name="...")` и следуй его инструкциям.
4. Нет → работай без скилла (обычный режим).

## Правила выбора

1. **Одна задача = один скилл.** Не грузить несколько.
2. **Конфликт** (например, текст + безопасность) — берёшь **основной**, про остальное помечаешь.
3. **Сложная задача** (>30 мин, >10k₽, новый класс) — `expert-council` (не одиночный скилл).
4. **Не нашли скилл** — работай без него, предложи создать позже.
5. **skill_view не должен ломать prompt caching** — вызывай один раз, не перезагружай.

## Пример

Пользователь: «напиши пост про статины для кардиологов, но без маркеров AI»

1. Контент → `humanizer` (убрать AI-маркеры)
2. Тема медицина → `aibolit` (проверить факты по PubMed)
3. Вывод: вызываю `humanizer` + `aibolit`, не `eli5` (это не объяснение «на пальцах»)
