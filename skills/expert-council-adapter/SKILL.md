# Expert Council Adapter — многоагентная команда

Адаптированный шаблон spawn из Auto-Company (MaxMiksa, 2563★).
Агент набирает 3–5 профилей Hermes для совместной работы над задачей.

## Зачем

Наши 6 fixed-профилей (Шерлок/Фемида/Дефендер/Маркетолог/Финансист/Айболит)
живут изолированно. Здесь — единый оркестратор, который из них собирает
временную команду под конкретную задачу. Не дублировать логику «набрать команду»
в каждом профиле — использовать этот навык как `expert-council-adapter`.

## Триггер

- Прямая задача: «Собери команду для [задача]» / «expert-council [задача]».
- Контекстная подсказка: задача пересекает 2+ профилей (напр. Kwork-кворок
  → Шерлок + Маркетолог + Финансист; security audit → Дефендер + Шерлок).
- Входной параметр `$ARGUMENTS` — описание задачи.

## Выбор агентов (2–5)

| Профиль | Ключевая роль | Когда брать |
|---|---|---|
| `sherlock` | Поиск вакансий / разведка | Любая задача с поиском, исследованием, конкурентным анализом |
| `marketer` | Позиционирование, контент, воронки | Маркетинг, лендинг, контент-план, Kwork-упаковка |
| `defender` | Безопасность, OWASP, секреты | Security audit, проверка кода, утечки |
| `financier` | Unit economics, pricing, LTV/CAC | Ценообразование, финмодель, Kwork-бюджет |
| `femida` | Юриспруденция, договоры, риски | Договоры, юр-чек, compliance, 152-ФЗ |
| `health` | Здоровье (Айболит) | Медконсультации, статин-симптомы (БЕЗ назначений) |

**Правила выбора:**
- Только нужные — не тащить всех.
- Учесть цепочку: от дизайна/стратегии → код → deploy → маркет.
- Избегать дублирования ролей (Шерлок + Маркетолог — OK; два маркетолога — нет).

## Пайплайн команды (адаптирован из Auto-Company)

### Шаг 1. Анализ и набор
1. Разобрать `$ARGUMENTS` на подзадачи.
2. Выбрать 2–5 профилей по таблице выше.
3. Сформулировать кратко, **почему** взяли каждого (записать для Игоря).

### Шаг 2. Spawn (через `subagent_type: general-purpose`)
Для каждого члена команды создать задачу с промптом:
```
Ты — [профиль] (Шерлок/Маркетолог/Дефендер/Финансист/Фемида/Айболит).
Задача: [описание подзадачи].
Выход: документ в docs/<role>/<task-id>.md
Ограничения: [память, риски, формат].
```

### Шаг 3. Сборка и консенсус
- Собрать выходы всех членов в единый `docs/<role>/<task-id>/summary.md`.
- Если есть расхождения — зафиксировать позиции каждого и передать Игорю.
- Итоговый вердикт — Игорь или Chief (по шаблону из `expert-council.md`).

### Шаг 4. Обновление консенсуса
Обновить `memories/consensus.md` (если применимо) или `docs/<role>/<task-id>/decision.md`.

## Формат вывода (обязательный)

```
## Состав команды
- [профиль]: почему (1 строка)
- [профиль]: почему

## Вердикт
[ГОПРОСТЬ/НЕТ-ГОПРОСТЬ] + одно предложение.

## Риски
- ...

## Документы
- docs/<role>/<task-id>/<member>.md
```

## Примеры использования

| Задача | Команда | Состав |
|---|---|---|
| Kwork-кворок | `expert-council Найти кворки по ботам Bitrix24` | Шерлок + Маркетолог + Финансист |
| Security audit | `expert-council Аудит кода Supabase edge` | Дефендер + Шерлок |
| Pricing для Snapog | `expert-council Подумать цены для OG-images API` | Финансист + Маркетолог |
| Юр-чек договора | `expert-council Проверить договор с erik0313233` | Фемида + Маркетолог |
| Эксперт-разбор новости | `expert-council Разбор AI-новости + экспертиза 6 профилей` | Все 6 (пилот ES-N) |

## Привязка к задачам

- **T-03** (регистратор — маршрутизация спецам): этот навык = «мозг» регистратора, маршрутизирующий задачу в команду из 3–5 профилей.
- **ES-N** (экспертные боты в ТГ): паттерн ложится на многоагентную дискуссию ботов — `@mention` каждого профиля.
- **AI-Scout expert analysis**: 8-фазный research pipeline (см. `skills/shrelock-research/`) можно подцепить как fallback для `expert_analysis` поля.

## Примечания

- Названия агентов — наши профили (`sherlock/femida/defender/marketer/financier/health`), **не** `.claude/agents/*` из Auto-Company.
- `docs/<role>/` — вывод каждого члена команды (привязано к профилю, не к `.claude/agents`).
- Структура `SKILL.md` — по канону Hermes (`---` frontmatter + `name`/`description` + `argument-hint` + `disable-model-invocation`).
- Китайский текст из оригинала `team/SKILL.md` убран; нотация адаптирована под ru.
