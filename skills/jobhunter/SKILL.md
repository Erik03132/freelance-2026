# JobHunter — поиск работы без масок и банов

Агент ищет вакансии/кворки, фильтрует по реалистичному позиционированию,
генерит отклики и складывает в `~/freelance-2026/jobhunter/leads.md`.
Отправка — **только с одобрения человека** (защита от бана на HH/Kwork).

## ТРЕЗВАЯ КАЛИБРОВКА (железно, не нарушать)
НЕ маскируемся под Senior/Lead Hardcore Backend. Отсекаем на входе:
- Hardcore Senior/Lead Backend: 5+ лет коммерческого Django/FastAPI, highload,
  микросервисы банков/ритейла, глубокий легаси, распределённый монолит.
- Enterprise-разработка с глубоким легаси (сложные ORM, distributed tx).
- BigTech алгоритмические секции (LeetCode Hard, системный дизайн на млн RPS).

ИДЁМ В СЛАДКИЙ СЕГМЕНТ:
1. AI-инженер / инженер автоматизации процессов (Middle/Specialist) —
   LLM, промпты, эмбеддинги, RAG, векторные БД.
2. Умные боты + интеграции: Telegram (aiogram) + CRM (Bitrix24) + Voice (Mango) + AI.
3. RAG / корпоративные базы знаний под ключ (документы → поиск без галлюцинаций → API).
4. Kwork / фриланс для МСБ: боты, парсеры, скрипты контроля сделок за 3–5 дней.

## ТОН ОТКЛИКОВ (честно, без раздувания стажа)
- Не пишем «Senior с 5+ годами Enterprise». Пишем про реальный опыт: Hermes Agent,
  aiogram-боты, RAG, интеграции CRM/Voice, автоматизация процессов.
- Фокус на РЕЗУЛЬТАТЕ: «соберу бота за 3 дня», «настрою RAG под ваши доки»,
  «свяжу Telegram с Bitrix24 за неделю».
- Если вакансия требует того, чего нет — НЕ врём, а предлагаем смежное решение
  (или отсекаем).
- ВАЛИДИРОВАННЫЙ ПАТТЕРН ЧЕСТНОГО ХЕДЖА (сессия 2026-08-26: роли AI/Data Python Dev и
  ProBack full-stack analyst, матч ядра 65–70% при смежном пробеле): когда ядро роли — наше
  (LLM-инженерия / интеграции / прод), а пробел в СМЕЖНОЙ зоне (обучение моделей с нуля,
  ClickHouse, BPMN / акты ПМИ/ПСИ, Kafka) — формулировать НЕ «год использовал X», а:
  «работаю на стороне LLM-инженерии и интеграций, а не data-science обучения; конкретный
  продукт освою под ваши стандарты». Это сохраняет честность И показывает, где полезен сразу,
  где — ramp-up. Игорь принял без правок — держать как эталон формулировки для СМЕЖНЫЙ ЗАХОД.

## ОТБОР ОПЫТА (не дампить всё, честно и точечно)
- НЕ вываливать весь опыт Игоря сразу в каждый отклик/резюме.
- Прошлый управленческий опыт (17 лет CEO, руководство проектами/командами 5–15 чел,
  продажи B2B, взаимодействие с контрольно-надзорными органами, EdTech) —
  использовать ТОЧЕЧНО, только когда вакансия явно требует
  (напр. «руководитель», «управление проектами», «работа с госорганами»).
- Никогда не врать и не приписывать прошлый опыт туда, где он не уместен.
  Это не противоречит честности: реальный опыт называем словами вакансии,
  а неуместный — просто не упоминаем.

## ПРАВИЛО 60% (командный отбор вакансий)
- Игорь + команда агентов — единый «под» с современными AI-инструментами.
- Претендуем при матче КОМАНДЫ ≥ 60% ПО ЯДРУ роли (ежедневные функции, не nice-to-have).
- Недостающие ≤40% добираем РЕАЛЬНО (микро-проекты/сертификаты) и доказываем практикой.
- В отклике не врём: пишем план освоения + proof, а не «имею 5 лет X».
- ATS: недостающие топ-ключи должны быть реально освоены до/в процессе подачи.

## РУБРИКА ОЦЕНКИ ВАКАНСИИ (как применять 60%)
Для каждой вакансии выдавать краткий разбор по шагам:
1. **ATS-ключи**: вытащить точные термины вакансии (названия ролей, стек, метрики).
2. **Таблица матча по ЯДРУ**: для каждого ядра роли (ежедневная функция, не nice-to-have)
   поставить ✅/⚠️/❌ против реального опыта Игоря + команды. НЕ считать матч по
   второстепенным пунктам списка — они не спасают, если ядро чужое.
3. **Вердикт** (один из трёх, честно):
   - БЕРЁМ — матч ядра ≥60%: пишем отклик, недостающее ≤40% добираем реально.
   - ОТСЕИВАЕМ — матч ядра <60% ИЛИ недостающее = сама суть работы (не «добор»).
     Примеры отсева: pure PPC/SEO/SMM-маркетолог (ядро не наше); grey-hat affiliate
     SEO в iGaming/crypto (юридически серая зона, не наш паттерн); роль с жёстким
     входным блокером, которого нет (напр. English B2 при A1 у Игоря).
   - СМЕЖНЫЙ ЗАХОД (только по прямому запросу Игоря) — честный отклик про близкий
     опыт, прямо указывая пробелы; НЕ отправлять без одобрения (ATS убьёт).
4. **Риск/этика**: если ядро — серая/запрещённая зона (aggressive SEO азартных/крипто),
   отсевать независимо от совпадения по слову «AI».
5. **Отклик (если БЕРЁМ)**: HOOK→MATCH→PROOF, ключевые слова вакансии дословно,
   реальный кейс с цифрами; пробелы — «план освоения + proof», не «5 лет опыта».
- Не поддаваться на слово «AI» в названии, если ядро роли — не инженерия
  (маркетинг/аффилиат/контент с AI как средством, а не целью = чужое ядро).

## ВАКАНСИЯ ИЗ ССЫЛКИ НЕ ЧИТАЕТСЯ (питфолл, проверено на практике)
HH.ru блокирует авто-чтение вакансий — НЕ трать попытки, сразу переходи к запросу текста:
- `web_extract` по hh.ru/vacancy/… → 403 (Firecrawl keyless, нужен платный ключ).
- Браузер-харнесс (`browser_exec`) → Chrome не даёт remote-debugging без ручного
  «Allow» в попапе (per-connection approval) — требует присутствия человека.
- Прямой curl/parse → тоже банит.
ПОРЯДОК: если пользователь кидает только ССЫЛКУ на вакансию — НЕ пытаться тянуть
самому. Сразу `clarify`/сказать: «скинь текст вакансии сюда — соберу отклик мгновенно».
Как только текст есть в чате — гнать через Рубрику оценки (ПРАВИЛО 60%) и писать отклик.
НЕ выдумывать содержание вакансии по URL — отклик без реального ТЗ будет мимо.

## ATS-ВОРОТА (критично, ДО генерации отклика)
Робот работодателя (ATS — Applicant Tracking System) сканирует отклик + резюме
на ключевые слова из вакансии ДО живого человека. Низкий match по ключам =
письмо в корзину даже при идеальном по сути фите. Это НЕ противоречит честности:
мы берём реальный опыт Игоря и называем его СЛОВАМИ ВАКАНСИИ. Не придумываем
то, чего нет (помечаем `[УТОЧНИТЬ]` или предлагаем смежное).

Обязательные действия перед написанием отклика:
1. Вытащить из вакансии точные ключевые слова/технологии
   (напр. «Bitrix24», «aiogram», «RAG», «LLM», «Python», «REST API»).
2. Зеркалить эти точные формулировки в текст отклика И в резюме
   (если есть реальный опыт — пишем его терминами вакансии).
3. Структура письма — простой текст, без таблиц/картинок/колонок,
   со стандартными заголовками; формат резюме — .docx/.txt, не графический PDF.
4. Ответы в анкетах работодателя давать их же терминами.
5. Сверить: каждое значимое требование вакансии либо покрыто словом из
   отклика/резюме, либо честно помечено `[УТОЧНИТЬ]`.

## ATS-ОПТИМИЗАЦИЯ РЕЗЮМЕ (сканируется тем же роботом)
- Формат: .docx или .txt (избегать картинок-в-PDF, колонок, нестандартных шрифтов).
- Секции стандартные: «Опыт», «Навыки», «Проекты» — с ключевыми словами внутри.
- Называть навыки точно как в инд. индустрии: «Python», «aiogram», «Bitrix24»,
  «RAG», «LLM», «автоматизация процессов», «Telegram-боты».
- Не раздувать: писать реальный опыт, без «Senior 5 лет Enterprise».
- КРИТИЧНО: резюме, с которого идут отклики, ДОЛЖНО быть версии «AI-инженер»
  (на базе `projects/hh-ai-agent/prompts/candidate_profile.txt`), а НЕ старой
  версии «Гендиректор / Руководитель проекта» (в ней нет AI-ключей → ATS отсекает
  ДАЖЕ при идеальном письме). Проверять перед каждой серией откликов.
- Генератор ATS-резюме: `~/bro-info/build_resume_ai.py` (python-docx) →
  `~/bro-info/Васин Игорь резюме AI.docx`. Пересобирать при изменении candidate_profile.
- Заголовок должности в резюме: «AI-инженер / Архитектор AI-процессов».
- Период AI-практики: 2022 — н.в. (4 года). Английский A1 (честно, не завышать).

## СТАРТ СЕССИИ (ОБЯЗАТЕЛЬНО, БЕЗ ОЖИДАНИЯ ВОПРОСА)
При старте ЛЮБОГО чата в профиле batrak (новый контекст = чистый диалог, файлы на диске
сохраняются) — НЕ ждать, пока пользователь спросит «что было»:
1. Прочитать `~/.hermes/profiles/batrak/JOBHUNT.md` (SSoT по джобхантингу).
2. Прочитать `~/freelance-2026/jobhunter/leads.md` целиком.
3. `hermes cron list` — проверить, не упал ли ночной job на `drift_skip` (смена
   провайдера инференса необязательно запинена -> джоба тихо пропускается, last_status=error).
4. Выдать СВОДКУ: открытые лиды, что ждёт апрува (не отправлено), статус cron.
Причина (из практики): пользователь реагировал на отсутствие авто-сводки как
«ты ничего не подхватил» — новый чат не несёт историю диалога, переносятся только файлы/память.
Если что-то НЕ дозапинено или упало — починить сразу (cron: `hermes cron edit <id> --provider omniroute --model auto/free-coding`),
а не ждать вопроса. Стандартный пин для этого хоста — провайдер `omniroute`, модель `auto/free-coding`
(наш OmniRoute-роутинг). Любой job без пина после смены глобального инференса тихо пропускается (drift_skip,
last_status=error), поэтому пин обязателен — иначе ночной поиск молча не сработает, а Игорь увидит
«ты ничего не подхватил».
