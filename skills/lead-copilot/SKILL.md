# Lead Copilot — скоринг лида и черновик ответа

Берёт сырой запрос (TG, почта, чат, пост, рекомендация), раскладывает его на 5 сигналов,
считает балл детерминированным скриптом и пишет короткий черновик ответа в тоне Игоря.
**Отправка — только руками Игоря.** Агент заканчивает на «черновик готов» и ждёт «да».

## Когда использовать

- Пришёл запрос на услугу (AI-агенты, RAG, боты, интеграции Bitrix24/Telegram, автоматизация процессов).
- Надо быстро понять, тратить ли время: P0 — в работу, P1 — уточнить, P2 — мимо.
- Нужен ответ, который не стыдно отправить: без лести, без «уникальных решений», с одним конкретным шагом.

Не использовать: спам-обходы, холодные массовые рассылки, парсинг закрытых чатов (см. «Границы»).

## Вход

Карточка лида — JSON, только факты из переписки. Чего нет — поле не заполняется (не выдумывать).

```json
{
  "id": "tg-2026-11-17-001",
  "service_match": "explicit",
  "budget_rub": 250000,
  "deadline": "2026-12-10",
  "deadline_days": null,
  "decision_maker": true,
  "request_date": "2026-11-15",
  "channel": "referral"
}
```

| Поле | Допустимо | Смысл |
|------|-----------|-------|
| `id` | строка | Идентификатор лида (без ПД) |
| `service_match` | `explicit` / `partial` / `none` / `true` / `false` | Совпадение запроса с ядром услуг |
| `budget_rub` / `budget` | число > 0 или `{"amount": N}` | Бюджет назван числом |
| `deadline` | `YYYY-MM-DD` | Срок назван датой |
| `deadline_days` | число > 0 | Срок назван в днях |
| `decision_maker` | `true` / `false` | ЛПР в диалоге |
| `request_date` | `YYYY-MM-DD` | Дата запроса (для свежести) |
| `channel` | `referral`, `recommendation`, `inbound`, `warm_inbound`, `reply`, `post_reply`, `event`, `network`, `outbound`, `cold`, `cold_outbound`, `scraped` | Откуда лид |

## 5 сигналов

| # | Сигнал | Вес | Уровни (измеримо) |
|---|--------|-----|-------------------|
| 1 | `service_match` — совпадение услуги/стека | 30 | **2** — в запросе явно наша услуга/стек (AI-агент, RAG, Telegram-бот, Bitrix24, автоматизация процесса). **1** — смежное/частичное. **0** — не наше |
| 2 | `budget` — бюджет и срок названы | 20 | **+1** — назван бюджет числом. **+1** — назван срок (дата или дни). Итого 0..2 |
| 3 | `decision_maker` — ЛПР в контакте | 20 | **1** — пишет владелец/директор/руководитель направления, решает он. **0** — посредник, менеджер без полномочий, «уточню у руководства» |
| 4 | `freshness` — свежесть запроса | 15 | **2** — ≤ 7 дней. **1** — 8–30 дней. **0** — старше 30 дней. Считается от `--as-of` |
| 5 | `channel` — канал/источник | 15 | **2** — рекомендация, тёплый входящий. **1** — ответ на пост, конфа, нетворкинг. **0** — холодный/спарсенный |

Балл = сумма (уровень / максимум уровня × вес), нормированная к 0..100. Считает только
`tools/lead_score.py`; классификацию уровней делает агент и показывает её человеку.

### Полосы и что с ними делать

| Полоса | Балл | Действие |
|--------|------|----------|
| **P0** | ≥ 75 | Черновик сразу, в работу: один созвон + смета |
| **P1** | 50–74 | Черновик с 1–2 уточняющими вопросами (бюджет/срок/ЛПР) |
| **P2** | < 50 | Время не тратить: короткий вежливый отказ или nurture, без продажи |

> **Пороги и веса — placeholder. LEAD-002 — PENDING, утверждает Игорь.**
> Свои цифры за согласованные не выдавать: в отчёте писать «пороги по умолчанию (placeholder)».
> Веса и пороги меняются файлом без правки кода: `--weights cfg.json`
> (`{"weights": {"service_match": 30, ...}, "thresholds": {"p0": 75, "p1": 50}}`).

## Порядок работы

1. **Карточка.** Выписать факты из запроса в JSON. Нет факта — нет поля. Ничего не додумывать.
2. **Классификация.** Проставить уровни по таблице и записать рядом, на чём основан уровень (цитата/факт).
3. **Скоринг.**
   ```bash
   python3 tools/lead_score.py --input leads/<id>.json --json --as-of 2026-11-17
   ```
   Сохранить в леджер: `--out leads/leads.jsonl` (повторный прогон с тем же `id` заменяет запись,
   дублей не будет).
4. **Черновик** по шаблону ниже, с поправкой на полосу (P0 — сразу к делу, P1 — вопросы, P2 — отказ).
5. **Propose→approve.** Показать Игорю: балл + разбор сигналов + черновик + что осталось неизвестно.
   Отправка — только после явного «да». Правки вносит Игорь или по его замечаниям.

## Черновик ответа

Тон Игоря: коротко, по делу, без лести и штампов. Первое лицо, один конкретный следующий шаг.
Максимум ~120 слов. Цену и срок не выдумывать: только из запроса или «уточню после вводных».

**Тёплый входящий / рекомендация (P0):**

```
Здравствуйте, <Имя>.

По задаче «<одна строка: что просят>» — берусь. Что дам: <результат 1>, <результат 2>.
Срок <N> рабочих дней, стоимость <X> ₽.

Чтобы не гадать с оценкой, нужен один вход: <пример выгрузки / доступ к тестовому контуру /
3 примера диалогов>. После него вернусь с планом на одну страницу: этапы, сроки, что нужно от вас.

Игорь
```

**Ответ на пост / чат (P1):**

```
Здравствуйте, <Имя>.

Видел запрос про <тема>. Делаю ровно это: <конкретика — стек и что запускал>. Близкая задача:
<один факт по делу, без воды>.

Предлагаю 15 минут созвона, сверим объём. Если совпадём — смета и срок в тот же день.

Игорь
```

**Отказ (P2):**

```
Здравствуйте, <Имя>.

Это не мой профиль — я занимаюсь <наша зона>. Чтобы не тянуть время: <кому/куда лучше>.

Игорь
```

Правила тона:
- Никаких «уважаемый», «буду рад сотрудничеству», «надеюсь на долгосрочное партнёрство», «уникальное решение».
- Не перечислять все навыки. Один-два релевантных, остальное — на созвоне.
- Не обещать того, чего нет в стеке. Не выдумывать кейсы и цифры.
- Один CTA. Не три.
- Не прикладывать файлы/презентации первым сообщением.

## Выход

- Леджер `leads/leads.jsonl` — по строке на лид: `id`, `score`, `band`, разбор сигналов. Без ПД.
- Сообщение Игорю: `балл/полоса → разбор 5 сигналов → черновик → чего не хватает → «отправлять?» (ждём «да»)`.
- После «да» и только после — отправка человеком. Агент не отправляет.

## Границы

- **Никаких юзерботов, авто-рассылок и массовых DM.** Мониторинг — руками Игоря + классификация агентом (LEAD-003).
- **Email-действия — только после LEAD-004:** проверка ПД (152-ФЗ) и рекламы (38-ФЗ ст. 18) через Фемиду. До этого скрипт и скилл email не трогают.
- **ПД не логировать.** Телефон, email, ФИО, ссылки на профили — не писать в леджер, claude-mem, логи и отчёты. В леджере только `id`, канал, баллы.
- **Не отправлять ничего людям без явного «да».** Propose→approve, как у Батрака: черновик — предложение, не отправка.
- **Не менять пороги и веса самостоятельно.** Только после апрува Игоря (LEAD-002), с записью в `ACTIVE_TASKS.md`.
- **Не выдумывать факты** (бюджет, срок, ЛПР, кейсы). Нет факта — сигнал пустой, балл ниже.
