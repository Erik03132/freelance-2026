# Единый реестр публикаций AI Bureau. Проект схемы

Образец — `projects/ai-marketing/docs/distribution/registry.json`. Там 31 запись на 24.11.2026. Реализация не создавалась. Это спецификация для одобрения.

Путь: `docs/distribution/registry.json` в рабочей копии сайта. Файл — единственный источник истины. KV-зеркало не используется.

## Идентификатор

`id = <slug>:post-N:<channel>`. Канал входит в идентификатор. Статусы Telegram, VK и Дзен независимы. На одну статью приходится одна запись на канал. Плюс запись `habr`.

## Поля

| Поле | Обязательно | Правило |
|---|---|---|
| `id` | да | уникальность проверяется гейтом |
| `slug` | да | совпадает с именем файла статьи |
| `post` | да | номер версии текста |
| `channel` | да | habr, telegram, vk или dzen |
| `status` | да | один из четырёх статусов |
| `plannedAt` | да | дата по плану |
| `publishedAt` | для posted | реальная дата |
| `url` | для posted | реальная ссылка |
| `messageId` | для telegram | номер сообщения от бота |
| `cover` | да | файл существует и отдаёт 200 |
| `sourceUrl` | для соцсетей | ссылка на исходную статью |
| `error` | для failed | причина по-русски |
| `note` | нет | пропуск слота или пояснение |

## Статусы

`draft`. `queued`. `approved`. `posted`. Из `posted` назад перехода нет. Статус `failed` допустим только с заполненным `error`. Пропущенный слот фиксируется в `note`. Удаление записи запрещено.

## Файлы рядом

Тексты лежат отдельно: `docs/distribution/posts/<slug>.post-N.md`. Версии для площадок лежат в `docs/distribution/{habr,telegram,vk,dzen}/<slug>.md`. Обложка лежит в `public/blog/<slug>-cover.png`. Проверка перед публикацией — ответ 200 на домене.

## Гейт

При внедрении появится `npm run dist:check` по образцу эталона. Он проверит уникальность идентификаторов и переходы статусов. Он проверит наличие файлов поста и обложки. CLI для агента строится по CP-1: flags, `--help` с примерами, `--dry-run`, идемпотентность и ненулевой код при ошибке.
