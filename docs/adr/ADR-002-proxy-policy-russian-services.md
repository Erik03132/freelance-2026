# ADR-002: Политика прокси и независимости от вендора

**Дата:** 2026-08-14
**Статус:** Accepted
**Контекст:** Часть каскадной системы (AGENTS.md §11). Нужен единый стандарт работы
с заблокированными в РФ ресурсами и защиты от vendor-lock агентного стека.

## Решение

### 1. Прокси — ТОЛЬКО для заблокированных в РФ ресурсов
Проксируются строго: OpenRouter, Gemini, Perplexity, OpenAI, Anthropic.
Российские сервисы и localhost — напрямую (прокси ломает их и даёт утечку/задержку):
- Bitrix24, Mango, Yandex, VK, Avito — без прокси.

В `.env`: схема всегда `socks5h://` (НЕ `socks5://` — локальный DNS ломает
заблокированные домены), плюс `NO_PROXY=bitrix24.ru,mango-office.ru,localhost,127.0.0.1`.
В коде модулей для российских API — двойная защита: `os.environ.pop` для `*_PROXY`
перед запросами.

### 2. Независимость от вендора (урок OpenClaw, Habr #1070296 / HZ-3)
> «Бизнес-модель твоей зависимости = твоя бизнес-модель.» (Peter Steinberger, OpenClaw)
> Оптимизировал стек под Anthropic — те за сутки отключили подписку одним письмом.

Принципы защиты от vendor-lock:
- **Model-agnostic по умолчанию.** Единый endpoint OmniRoute (`OPENAI_BASE_URL`),
  маршрутизация по цене/латентности/доступности + auto-fallback. Ни один агент
  не хардкодит одного провайдера.
- **Открытая лицензия = страховка.** Инструменты стека (OpenCode MIT, наш код)
  не зависят от закрытого SaaS, который могут «выключить». Закрытые API только
  как опциональный backend с fallback.
- **Свой inference-слой.** OmniRoute + локальные модели (whisper/llm) снижают
  критическую зависимость от внешних лимитов.
- **Нет single-point-of-failure в промптах.** Логика агента воспроизводима при
  смене модели (cache-aware переключение только на границе задач, AGENTS.md ND-1).

### 3. Тайпсквоттинг / supply-chain (HZ-4)
Перед установкой пакета проверять официальный источник (ai-defender `scan_typosquat`):
PyPI-дубликат vs официальный npm-скоп (пример: `deepseek-harness` PyPI — тайпсквоттинг,
официальный `@deepseek-ai/dsh`). Install-гигиена через githooks/no-secrets.

## Альтернативы
- Прямые ключи провайдеров в коде — отвергнуто: vendor-lock + утечка (SEC-аудит 02.08).
- Единый закрытый SaaS-агент — отвергнуто: kill-switch риск (OpenClaw-урок).

## Последствия
- Все агенты ходят в модели через OmniRoute, не напрямую к вендору.
- РФ-сервисы — без прокси (двойная защита pop в коде).
- ai-defender покрывает supply-chain (typosquat) и untrusted-data (BK-3).
