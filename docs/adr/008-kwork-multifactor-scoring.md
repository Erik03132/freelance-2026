# ADR-008: Многофакторный скоринг кворков (v2 finder)

- **Статус:** принято (2026-08-27)
- **Контекст:** ADR-007 задал конвейер, но реализация (kwork_finder.py v1) брала
  ВСЁ, что попало под regex «сладкого сегмента», и **игнорировала**:
  1) число уже поданных заявок (попадались кворки с 80+ конкурентами);
  2) качество/историю заказчика (кол-во заказов, рейтинг, верификация);
  3) реальный матч наших навыков с ТЗ (отсюда баги вроде «создать видео» в откликах).
- **Проблема:** отклики уходили на не-наши задачи и в задавленные толпой кворки.
- **Решение:** решать кворк не по текстовому совпадению, а по **4-осевому скорингу**.

## 1. Четыре оси (каждая 0..100)
| Ось | Что меряет | Источник |
|-----|-----------|----------|
| `skill` | % покрытия ЯДРА требований нашим стеком | `candidate_profile.txt` (SSoT) |
| `competition` | чем МЕНЬШЕ заявок — тем ВЫШЕ | парсинг «Предложений: N» |
| `client` | заказы + рейтинг + верификация заказчика | парсинг карточки/страницы |
| `budget` | бюджет против якоря 1500₽/ч | парсинг «до N руб» |

Веса по умолчанию: skill 0.45, competition 0.25, client 0.20, budget 0.10.

## 2. Матрица навыков (SSoT)
- `OUR_SKILLS` — ~17 канонических навыков с regex (python, llm, rag, telegram_bot,
  bitrix24, mango_voice, parsing, automation, api, web, sql, docker, content_gen,
  data_analysis, transcription, avito_vk, ui_proto). Это то, что МОЖЕМ по профилю.
- `EXCLUDE_SKILLS` — жёсткий отсев (HARD_EXCLUDE → X): video/монтаж/3D/логотипы/
  мобилка/игры/hardcore-backend/копирайт/перевод/SMM/фото. **Защита от бага**
  «видео создавать» в отклике.

## 3. Правило 60% (уточнение из JOBHUNT.md)
- Матч ядра ≥ 60% → берём. 40–59% → кандидат (B, решает Игорь). < 40% → X.
- Заявок > 80 → мгновенный X (задавлено). 50–80 → B.
- Клиент с 0 заказами ИЛИ рейтинг < 3.0 → НЕ A (принудительно B/рассмотрение).
- Бюджет < 50% якоря → демпинг, X.
- Итоговый скор = взвешенная сумма; порог A = 60 (настраивается флагами CLI).

## 4. Решение A / B / X
- **A** — пишем ЧЕРНОВИК отклика (стандарт v3) в outbox + leads. Ждёт ручного апрува.
- **B** — кандидат: только строка в leads «решает Игорь». Черновик НЕ пишем.
- **X** — отсев с причиной в логе/leads (HARD_EXCLUDE / задавлено / демпинг / <40% матч).

## 5. Анти-бан + free-only (наследуем из ADR-007)
- Задержки 30–60с между страницами, ротация UA, cookies kwork.json, без прокси-env.
- Никаких платных LLM-вызовов при скоринге. Никакого auto-send.

## 6. Доказательство (TDD + demo)
- `cron_jobs/test_kwork_finder.py` — 16 тестов на чистую логику (extractors, HARD_EXCLUDE,
  матч, заявки, слабый клиент). Все зелёные.
- `python3 kwork_finder.py --demo` — прогон синтетики без сети: показывает,
  что видео/логотип/мобилка → X, парсер при 85 заявках → X, Telegram-бот → A,
  слабый клиент → B.

## 7. Обратная связь (обновление ADR-007 §11)
- Игорь помечает «выиграл / нет» в `leads.md`; пороги --min-skill-a / --max-proposals-x
  корректируются под реальный win-rate.
