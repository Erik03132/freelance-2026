# ADR-009: Починка рантайма kwork_finder — почему ночной поиск был бесполезен

- **Статус:** принято (2026-08-27)
- **Контекст:** ADR-008 поднял качество *решения* (A/B/X), но после прогона
  выяснилось, что сам **сбор данных** не работал. Ночной поиск возвращал 0
  кворков и/или ложные A. Корень — три независимых бага в рантайме скрайпера.

## 1. Баг A — мёртвый системный прокси macOS ломал headless Chromium
- **Симптом:** `fetch_projects` падал с `net::ERR_CONNECTION_REFUSED` на
  `kwork.ru/projects`, хотя `curl` давал HTTP 200.
- **Причина:** в окружении терминала висит `http_proxy=socks5h://...` (живой
  SOCKS у провайдера), но Chromium **headless-shell** не умеет `socks5h`
  (только `socks5`/`http`) → `ERR_NO_SUPPORTED_PROXIES`, а без явного запрета
  читал системный прокси и уходил в отказ.
- **Решение:**
  1. В `launch()` убран `proxy=None` — он заставлял Playwright брать системный
     прокси. Оставлен только флаг `--no-proxy-server` в `launch_args` (прямой
     заход, РФ-сервисы по ADR-002).
  2. CLI-прогоны запускаются с `env -u http_proxy -u https_proxy ...` (сброс
     proxy-переменных в subprocess, без трогания `.zshrc` — см. правило
     безопасности сети).

## 2. Баг B — `wait_until="domcontentloaded"` не наступал на Kwork
- **Симптом:** после починки прокси — `Timeout 45000ms exceeded`, 0 карточек.
- **Причина:** Kwork держит висячие запросы (онлайн-счётчик/SSE), событие
  `domcontentloaded` не стреляет.
- **Решение:** `wait_until="commit"` + явное `wait_for_selector(
  "a[href*='/projects/']")` + небольшая пауза на дорисовку SPA.

## 3. Баг C (главный) — ложные A из-за мусора в `cardText`
- **Симптом:** решение A получали кворки «Работа без навыков», «Доработать
  сайт», «Оформление сообщества ВК» и т.п.
- **Причина:** `fetch_projects` брал `cardText` со всего DOM-дерева карточки —
  туда попадали категории, «похожие кворки», футер. `score_skill_match`
  находил там один случайный маркер (напр. «бот»/«автоматизация») и выдавал
  match=100%, и кворк без реального ТЗ шёл в A. Это и делало ночной поиск
  «бесполезным» — outbox забивался мусором.
- **Решение:**
  1. `fetch_projects` больше НЕ тащит `cardText`. `desc` = только заголовок.
     Бюджет/заявки/клиент из карточки не парсятся (всё равно мусорные).
  2. `evaluate()` получил защиту 0.5: кворк **без реального ТЗ** (desc не длиннее
     заголовка) → решение B («матч недостоверен»), никогда не A.
  3. `main()` перестроен: предфильтр по заголовку (есть ли маркер нашего
     навыка) → для прошедших **всегда** стягивается РЕАЛЬНОЕ описание через
     `fetch_job_detail()` и решение принимается уже по нему. Кворки без маркеров
     в заголовке сразу B (без траты запросов на детали).

## 4. Ограничение платформы — Qrator rate-limit
- **Симптом при целевом поиске:** при стягивании деталей 15 кворков подряд
  Kwork/Qrator начинает массово отдавать `ERR_CONNECTION_REFUSED` (один IP,
  бёрст).
- **Решение (стратегия):** не стягивать детали пачкой. Собирать заголовки
  листинга (дёшево, 1-3 страницы), выбирать 1-2 сладких кандидата, проверять
  реальное ТЗ **поодиночке** с большими паузами. Для ночного cron — лимит
  ~3-5 деталей за прогон, задержки 30-60с (сохранено из ADR-008).

## 5. Тесты
- Добавлены в `test_kwork_finder.py`: `test_false_A_by_title_only_is_B`,
  `test_real_desc_lifts_to_A`. Существующие приведены к «реальному ТЗ»
  (desc длиннее заголовка). Итого 18 тестов, все зелёные (`python3 -m unittest`).

## 6. Итог для Игоря
Ночной поиск теперь: (а) реально доходит до Kwork, (б) не выдаёт ложные A по
мусорным маркерам, (в) пишет черновик только по РЕАЛЬНОМУ описанию кворка.
Плюс найденный вручную живой кандидат доставляется как ссылка + черновик
письма на ручной апрув (без auto-send, анти-бан).
