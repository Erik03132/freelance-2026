# hermes-hq — control plane для команды Hermes-профилей

**Автор/источник:** `smkamranqadri/hermes-hq` (29.08.2026, GitHub, https://github.com/smkamranqadri/hermes-hq) · ★0 · MIT · активен (pushed 31.08.2026, early development)

**Суть (2-3 строки):)** портативный оркестратор для команды Hermes-агентов: проекты → задачи → **реальные** агентские сессии с читаемым статусом и списком «нужен ты». Движок на SQLite (диспетчер, одна постоянная сессия Hermes на задачу, контракт завершения, автоматический reviewer-gate) + милитари-UI (5 человеческих статусов: бэклог/очередь/работает/нужен ты/готово, каждая с action что разблокирует). One-command установка на сервере где уже есть `hermes`.



**Стек:** Python ≥3.11 (uv) + Node ≥22 + Hermes CLI. SQLite-хранилище, диспетчер, supervisor (systemd/s6, `hermes-hq service status|restart|update|auto-update`). Состояние-машина: planned/waiting_approval/ready/running/needs_review/rework/blocked/failed/stalled/done/manual.



**Что применимо у нас:** [ЧАСТИЧНО/в очередь] — у нас 6 Hermes-профилей (sherlock/femida/defender/marketer/financier/health) + Chief-маршрутизатор, но **нет читаемой панели «кто что делает / что застряло»** между сессиямии координация идёт через ACTIVE_TASKS.md вручную. hermes-hq предлагает движок «одна сессия на задачу + reviewer-gate + список «нужен ты»» — ровно наша дыра в оркестрации командой агентов（ORCH, ARCH-001）. Берём как паттерн (не зависимость: ★0, early.



**Цифры/бенчмарки:** громких цифр нет. Проверено через API: ★0, MIT, pushed 31.08. «Early development» — автор сам признаёт незавершённость (data views/write flows в разработке)。



**Trade-off:** движок обещает дисциплину «контракт завершения + ревьюер» (анти-брошенных задач), но требует стабильного `hermes` на хосте и одной сессии на задачу (дорого по токенам/памяти если задач много)。 UI пока ранний.



**Сравнение с альтернативами:** vs наш кастомный дашборд `:8890`(модели/провайдеры, это мониторинг, не оркестратор задач. vs `hermes-control-interface`/`titan-agent-dashboard`(веб-dashboards, мониторинг, без движка сессий → пропущены. hermes-hq — единственный с движком «сессия→задача→ревью», не просто «смотрим на агента».

**Подводные камни (из источника):** (1) ранняя стадия (★0, автор пишет «third attempt» — предыдущие не выжили; (2) одна сессия Hermes на задачу = расход токенов/памяти линейно по задачам; (3) своб. сессий не переживает рестарт хоста если нет supervisor-настройки;(4) «контракт завершения + критик» может блокировать быстрые задачи неоправданным ревью.



**Когда НЕ применять:** пока у нас нет стабильного фонового Hermes-раннера с авто-push (VPS-блок T-08, Timeweb FWaaS) — сначала чини базу, потом оркестратор. Пилот — на 1-2 профилях, не на всех 6。
