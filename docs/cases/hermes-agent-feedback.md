## hermes-agent-feedback — агент как потребитель, не процессор
**Автор/источник:** Лев Немировский (Apokalepsis), Альфа-Банк, Habr 1072770 (21.08.2026) — опыт эксплуатации Hermes Agent (локальная Qwen3.6-35B-A3B через LM Studio, скиллы + крон для обработки почты/встреч).
**Суть (2-3 строки):** Попытка сделать детерминированный пайплайн ВНУТРИ агента провалилась: при сбое скрипта агент обходил его, сам писал новые и затирал сами скиллы («каша»); крон в «тихом» режиме маскировал падения → каскад. Решение: обработку вынести в детерминированный код (Go), Hermes оставить потребителем БД/векторной коллекции. Подтверждает Anthropic «Building Effective Agents».
**Стек:** Hermes Agent, Qwen3.6-35B-A3B (LM Studio), Go-приложения, векторизация части данных, крон.
**Что применимо у нас:** [ДА] — 3 фичи: (ES-22) write-protect скиллов от самоизменения агентом (skills-lib read-only есть, активные — нет), (ES-23) явный failure-сигнал у крон-задач (не «тихий» режим), (ES-24) дисциплина «агент = потребитель, не процессор» (подтверждает AP-1/HT-3, поднять до явного правила). Не берём: Docker-на-Mac пути (ставим локально), смена адреса локальной LLM (operational).
**Действие:** [ ] ES-22..ES-24 → ACTIVE_TASKS (секция «🧠 Эксперт-сессия»)
