# ES-24: Дисциплина «агент = потребитель, не процессор данных»

## Суть принципа

Детерминированная обработка (парсинг, агрегация, дедуп, сортировка, фильтрация,
хеширование, нормализация) — это КОД (скрипты / tools / execute_code), а не
промпт. Агент (LLM) вызывается ТОЛЬКО для суждения над результатом: извлечение
смысла, классификация, скоринг, синтез. Это stateless-дизайн: тяжёлые вычисления
в коде, агент — тонкий потребитель БД / векторной коллекции / инструмента.

Источник: Anthropic «Building Effective Agents» — workflow для известного пути,
агент — для неизвестного.

## Аудит целевых проектов (ES-24: Шерлок, sinergy, Фемида, freelance-agent)

### Sherlock (профиль)
- Роль: разведчик (web_search / web_extract / browser_exec), только факты+источники.
- Обработка: агент НЕ парсит и не агрегирует в промпте — возвращает сырые находки
  с цитатами. Секреты не ищет и не логирует (границы в SOUL.md).
- Вердикт: ✅ соответствует (judgment-light, факты наружу).

### sinergy (проект) — `src/lib/sinergy/source-processor.ts` и смежное
- Дедуп: `shortHash()` (хеш), проверки по `original_url` и `title` в Supabase — КОД.
- Фильтр шума: `isContentBanned()` (BANNED_KEYWORDS) — КОД.
- Сортировка/дедуп в `discovery.ts`: `seenTitles = new Set(...)`, `.filter()` — КОД.
- LLM (`askGemini`) используется ТОЛЬКО для: семантического извлечения идей из
  текста в структурированный JSON и классификации (`classify/route.ts`) — это
  суждение, а не детерминированная обработка.
- Fallback «сырой» путь (`saveRawItems`) сохраняет без LLM, чтобы фид не падал.
- `agents/orchestrator.ts`: LLM-дебаты (optimist/skeptic/builder) для СИНТЕЗА
  синергий — суждение; детерминированная часть (`scoredPairs.sort`, diversity
  filter) — КОД.
- Вердикт: ✅ соответствует. Тяжёлая работа в коде, LLM — потребитель/судья.

### Femida (профиль, юр-секреты)
- Правило 1 (цитата+источник) и Правило 2 (актуальность редакции) зафиксированы в
  SKILL.md — LLM обязан ссылаться, код/промпт не фабрикует факты.
- Вердикт: ✅ соответствует (provenance = агент потребляет источник, а не генерит).

### freelance-agent (проект) — `src/mcp-servers/bitrix.ts`, `design.ts`
- Bitrix MCP: детерминированные вызовы API через `axios`, парсинг ответов в коде;

- Design (Rembrandt): генерация ассетов через инструменты (Stitch/SVG) — КОД-тулы,
  суждение (визион) — у LLM.
- Вердикт: ✅ соответствует.

## Итог аудита

Все 4 целевых проекта УЖЕ кодируют принцип ES-24 (детерминированное → код,
агент → суждение). Отдельного выноса обработки из агента не требуется — он
фактически сделан в процессе постройки стека (AP-1/HT-3). Единственный
оставшийся шаг — ПОДНЯТЬ принцип до явного правила в AGENTS.md (каскад), чтобы
новые агенты не регрессировали.
