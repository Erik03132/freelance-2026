# Предложения по переработке (без изменения кода)

Принцип: не переделывать lime-polish-дизайн (он зафиксирован в `ai-bureau-site/DESIGN.md` и Verified на проде), а добавить недостающие страницы, связи и факты. Все пункты — предложения, требующие одобрения.

## Новая структура сайта

```
/                       главная. Услуги со ссылками. Три кейса с цифрами. Этапы. FAQ. CTA.
/services/              индекс услуг. Шесть карточек. Цена и срок.
/services/<slug>/       шесть существующих страниц. Уникальный текст. BreadcrumbList. Offers.
/cases/                 индекс кейсов. Заказчик. Задача. Цифры. Дата. Метод.
/cases/<slug>/          кейс с методикой. Ограничения обязательны.
/blog/                  индекс статей. Десять статей по дорожной карте.
/blog/<slug>/           статья. BlogPosting. Автор. Дата. AEO-блок. Источники.
/about/                 кто мы. Опыт. Реквизиты. ИНН.
/contact/               контакты. Рабочий канал заявки.
/privacy/               канонический URL. Сейчас два адреса: /privacy и /privacy.html.
/llms.txt               свод для LLM.
/llms-full.txt          расширенная версия из SSoT.
/sitemap.xml            генерация из контента. lastmod — дата правки.
/robots.txt             явные AI-боты.
```

## Главная — что поменять в содержании

1. H1 оставить; добавить под ним **одну проверяемую цифру** (например, «пилот 2–4 недели» — только если владелец подтвердит) и понятный следующий шаг. Сейчас «полный цикл», «результат», «новая операционная система» — абстракции без подтверждения.
2. Карточки услуг сделать ссылками (AIB-02). Это самый дешёвый прирост внутренних ссылок.
3. Раздел «Кейсы» переименовать в «Типовые сценарии» (так он и устроен) или наполнить реальными кейсами с датой, заказчиком, метрикой и оговоркой «результат зависит от продукта и цен».
4. Добавить блок цен/сроков: на главной «стоимость после аудита», на странице RAG уже есть «от 300 000 ₽» — привести к единому SSoT, иначе цифры конфликтуют.
5. Форму заменить на рабочий канал или подключить endpoint (AIB-01); цель Метрики ставить только по успешному ответу.

## Страница услуги — единый стандарт

Сейчас у всех шести одинаковые «Как это работает» и «Что получите». Предлагаемая последовательность секций:

1. **Проблема заказчика** — 2–3 предложения, одна боль, одна цифра/наблюдение.
2. **Сценарий** — кто и что делает до и после; ссылка на соответствующий кейс/статью.
3. **Что делаем** — 3 шага с артефактами (например, «карта процессов», «пилот на 20 документах»).
4. **Интеграции и ограничения** — 1С/Bitrix24/amoCRM/Confluence; честно, где не работает.
5. **Цена и сроки** — вилка из SSoT, а не разная по страницам.
6. **FAQ** — сохранить `<details>`, уникальные вопросы под услугу.
7. **CTA** — один путь заявки, без мёртвой формы.

Плюс `BreadcrumbList` (сейчас `<div aria-label>`), `Service.url/offers/areaServed`, `@id` для связки с `Organization` и статьями.

## Контент и голос

Голос Шекспир v2: тезис в первой строке, «вы/мы», «заказчик», компания — «бюро», жаргон только с расшифровкой («поиск по документам (RAG)»), цифры не выдумывать, одна короткая ирония на текст, обещания чудес — табу. Полная адаптация — `../roadmap/VOICE_V2_AI_BUREAU.md`.

## Границы

- Не трогать `ai-bureau-site` (Lovable) и старый `ai-bureau` (Astro, `ai-bureau.pro`) без отдельного решения: они **не** обслуживают домен `ai-bureau.online`.
- Не править прод-репо без одобрения: деплой GitHub Pages происходит из `main`, любые правки сразу видны на домене.
- Изображения/обложки не генерируются до утверждения шаблона.
