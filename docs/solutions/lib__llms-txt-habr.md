## Ключевые тезисы

- **llms.txt — markdown-файл в корне сайта с картой контента для ИИ-систем.** Предложен Джереми Ховардом (Answer.AI) 3 сентября 2024.
- **Краулеры ИИ его практически не читают:** 408 обращений из ~515 млн бот-событий за 90 дней (Limy.ai, май 2026). Менее 0.0001%.
- **Ни одна крупная платформа официально не поддерживает llms.txt.** Джон Мюллер (Google, 17.06.2025): «no AI system currently uses llms.txt».
- **Для русских сайтов — Алиса AI и GigaChat — файл бесполезен.** Яндекс и Сбер не делали заявлений о поддержке.
- **Единственный реальный кейс — IDE-агенты** (Cursor, Cline, Copilot Chat) для документации разработчиков. Mintlify, Stripe, Vercel активно используют именно для этого.

## Паттерны/фреймворки

- **Рыночный нарратив vs реальность:** Adoption вырос с 951 до ~12 174 доменов (к сентябрю 2025), но потребление не растёт — Mintlify дала скачок цифр через автогенерацию.
- **Разница между "вести свой" и "читать чужой":** OpenAI, Anthropic, Perplexity ведут llms.txt для своей документации, но не читают чужой при формировании ответов.
- **Для маркетинговых сайтов:** лучше тратить ресурсы на качество контента, Schema.org и ссылочную массу, а не на llms.txt.

## Применимо к нам

- **GEO/AEO стратегия:** llms.txt НЕ является переменной видимости в ИИ. Приоритет — качество контента по ЭПОС (Expertness, Usefulness, Originality, Content-richness), Schema.org, позиции в органике.
- **Если делаем llms.txt:** только для dev-документации (API, библиотеки), не для маркетинговых страниц.
- **Риск:** автоматически сгенерированный файл без приоритезации — потенциальный вектор для спам-инъекций.

## Оценка

- **Полезность:** 7/10 — хороший разбор мифа с конкретными данными
- **Актуальность:** высокая (август 2026)
- **Цитирование:** стоит использовать в статьях про GEO/AEO как аргумент против ложных ожиданий от llms.txt
