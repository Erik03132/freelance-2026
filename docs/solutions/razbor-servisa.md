# razbor-servisa — скилл «сторонний сервис → CLI для агента»

**Что:** MIT-скилл для Claude Code (Ntmib, август 2026). Метод-рефлекс из 7 шагов: когда у внешнего сервиса нет удобного API — подсмотреть, как сайт разговаривает со своим сервером (F12 → Network → Copy as cURL), собрать маленький CLI под стек проекта, оформить отдельный Skill, чтобы агент звал команды по человеческой фразе.
Источник: <https://github.com/Ntmib/razbor-servisa> (7★ / 4 fork, 2 коммита, оба Co-Authored Claude Opus 5 — человек только заливал и фиксил README, метод писал агент). Файлы, которые реально читал: `SKILL.md`, `references/curl-to-cli.md`, `references/rossiyskie-osobennosti.md`.

**Суть (метод за 1 минуту):**
1. **Развилка A/B/C** доступа: открытый API → собираем по докам; API кривой → доки + реверс; API нет → только реверс. SKILL.md явно требует не угадывать ветку, а проверить (`WebSearch` / спросить Игоря).
2. **Реверс** = пользователь открывает свой кабинет, F12 → Network → щелкает нужный раздел → Copy as cURL в чат. Агент разбирает: URL/method/заголовки/тело/ответ → мини-спека endpoint'ов.
3. **CLI под стек проекта** (Node если `package.json`, Python иначе). Одна команда = одна задача. JSON-вывод с `--json`. `--help` с примерами. Секреты → `.env`.
4. **Skill поверх CLI** — короткая инструкция «по каким фразам звать», кладётся в `~/.claude/skills/<имя>/SKILL.md`.
5. **Чек-лист безопасности** (раздел §0): только свой кабинет; чтение свободно, изменение — только после явного «да»; капча = стоп; правила сервиса на стороне Игоря.

**Вес (диск):** ~20 KB (3 markdown-файла). Никаких зависимостей, ничего не ставится. Текст.

**Когда юзать у нас:**
- **Шерлок/Кулибин** получили задачу «интегрироваться с Х» (маркетплейс, банк, CRM, сервис рассылок) → первое действие = развилка A/B/C, а не «давай поставим официальную библиотеку». Для РФ-сервисов (Ozon Seller, WB, Т-Банк, ЮKassa, Mango, Bitrix24) ветка C — норма, не исключение.
- **Ботман** строит Mango/Bitrix24-бот → если у кабинета кривой/полу-открытый API, реверс через браузер владельца сразу даёт полный набор операций.
- **Angela outbound** — если захотим подключить провайдера телефонии/рассылок без нормального API (типичный кейс), это наш единственный путь к автоматизации без ручной возни.
- **AI-Scout / Curator** — когда надо собирать метрики из чужих кабинетов (Ozon Performance, Я.Метрика API урезанный), реверс снимает то, что API не отдаёт.

**Риски/ограничения (экспертиза, авг-2026):**
- **Зависимость от браузера пользователя.** Скилл ожидает, что у пользователя есть реальный браузер с его авторизацией. У нас в OpenCode/Codex CLI-режиме — есть; в Hermes-Desktop через `browser_exec` (Browser Use MCP) — есть, но с оговоркой: сессию надо поднимать заново (нет cookie пользователя). **Workaround:** для Hermes-Desktop подключать remote daemon с `session=` для изоляции от дефолтной, явно говорить пользователю «залогинься в X».
- **Скилл написан под Claude Code.** Прямой перенос в OpenCode/Hermes: работает (формат SKILL.md одинаков), но `~/.claude/skills/` → `~/.hermes/skills/` (или `~/.config/opencode/skills/`). У нас скиллы синхронизированы симлинками — копировать только в один каталог, остальное подхватится.
- **Юридический риск.** Скилл сам предупреждает: «правила сервиса на вашей стороне». Для РФ (152-ФЗ, лицензионные соглашения площадок) это серьёзнее, чем кажется. Добавить в `agent-lab/foundation/LEGAL_CHECKS.md` чек-лист «перед запуском реверса: ToS сервиса, хранение токенов, передача третьим лицам». Если сервис прямо запрещает — даже через свой аккаунт не делать.
- **Динамические заголовки (CSRF, fingerprint).** `curl-to-cli.md` упоминает — у нас в `agent-lab/` пока нет шаблона CLI, который их подхватывает. Если появится — отдельный reference `dynamic-headers.md`.
- **Open-source софт ≠ закрытый SaaS (§5, последний абзац).** Скилл явно отделяет: для OSS-десктоп-утилит есть другие инструменты (генерация CLI из исходников), этот скилл бесполезен. У нас в `freelance-agent/` и `agent-lab/` OSS-инструменты редки, но если попадётся — не пинать razbor-servisa понапрасну.
- **Звёзд мало (7★), 2 коммита, всё от автора+Claude.** Риск: ни один внешний пользователь не подтвердил на живой интеграции. Авторская уверенность, не peer-reviewed. **Перед продом на Mango/Bitrix24 — обязательно пилот на тестовом аккаунте.**

**Статус:** **кандидат, внедрить как reference для Шерлока/Кулибина**, не как обязательный скилл для всех агентов. Сначала пилот: один реальный сервис без API (например, Mango Office личный кабинет или WB Seller в части аналитики) → собрать CLI → оформить Skill → убедиться, что агент вызывает по фразе. После пилота — апгрейд до «обязательного» в `agent-lab/skills/sherl-research/` и в `agent-lab/skills/botman-creator/`.
