# ADR: Архитектура Telegram Gateway для Мультиагентного Совета (ES-N)

**Дата:** 2026-08-23  
**Статус:** Принято  
**Контекст:** Проект `freelance-2026` / Мультиагентная система Hermes Agent / Задача ES-N  
**Автор:** Игорь Васин, Hermes Agent  

---

## 1. Контекст и проблема
В экосистеме Hermes настроены 6 специализированных профилей экспертов (`sherlock`, `femida`, `defender`, `marketer`, `financier`, `health`), а также координатор (Chief / Personal).
Для оперативного взаимодействия и фоновой работы 24/7 требуется:
- Доступ ко всем 6 экспертам из мессенджера (Telegram).
- Возможность вызова конкретного эксперта через `@mention` или отдельного бота.
- Поддержка полного 6-ролевого Совета (Expert Council) для стратегических задач.
- Работа шлюза 24/7 на VPS Timeweb без привязки к локальному Mac.

---

## 2. Принятое решение
1. **Топология ботов и шлюзов (Telegram Gateway):**
   - **Вариант А (Единый координатор / Multi-Topic Supergroup):** Единый Telegram-бот с темами (topics) / префиксами маршрутизации для каждого профиля. Chief принимает сообщения и делегирует через `delegate_task` с контекстом соответствующего `SOUL.md`.
   - **Вариант Б (Сетка специализированных ботов):** Отдельный Telegram-токен на каждый профиль (`hermes gateway run --profile <name>`) под управлением `systemd` на VPS.
2. **Маршрутизация и Совет Экспертов (Expert Council Mode):**
   - Точечные вопросы: роутинг на конкретного эксперта (`femida` — право, `defender` — безопасность, `sherlock` — разведка рынка).
   - Комплексные / стратегические вопросы (порог >10 000 руб. / риск): запуск параллельного опроса всех 6 экспертов через `delegate_task` с агрегацией в единый `Chief Summary` (4 вердикта: Резюме, Риски, Рекомендация, План).
3. **Хостинг и безопасность:**
   - Развертывание сервисов шлюза на Timeweb VPS (`217.149.23.113`) под `systemd`.
   - Доступ к Telegram API через no-proxy / внешний IP сервера.
   - Защита данных: соблюдение 152-ФЗ / PII (обезличивание чувствительных данных перед отправкой в облачные LLM).

---

## 3. Последствия
### Положительные:
- Полный доступ к команде AI-экспертов из смартфона 24/7.
- Четкое разделение ответственности и специализаций без размытия системного промпта.
- Автономный запуск Совета Экспертов по триггеру.

### Риски и ограничения:
- Контроль расхода токенов при вызове полного 6-ролевого Совета (решается использованием быстрых tier-0/tier-1 моделей через OmniRoute/OpenRouter).
- Необходимость поддержания актуальности `SOUL.md` файлов профилей.
