# Agentic AI Guide (NotebookLM)

## Суть (2-3 предложения)
Agentic AI описывает автономные системы, которые планируют, используют инструменты, хранят и обновляют информацию, проверяют свои действия и корректируют поведение для достижения заданной цели. Книга предлагает структурированный путь обучения — от основ программирования и математики до продвинутых тем мультиагентной orchestration, наблюдаемости и безопасности. Ключевой механизм поведения агента — цикл ReAct с внутренним scratchpad‑ом и чёткими условиями остановки.

## Ключевые идеи
1. Agentic AI объединяет планирование, использование инструментов, память (рабочая, эпизодическая, семантическая, внешняя) и самооценку для достижения цели.  
2. Обучение построено из семи фаз: основы (Python, математика, инженерия ПО), core AI/ML, LLMs и промпт‑инжиниринг, архитектура агентов, инструменты и фреймворки, производство и надёжность, продвинутые темы.  
3. Основной паттерн поведения — ReAct (Reason‑Act‑Observe) со scratchpad‑ом и условиями остановки.  
4. Память агента реализуется через несколько типов (рабочая, эпизодическая, семантическая, внешняя) и может быть общей в мультиагентных системах.  
5. Мультиагентные системы состоят из оркестратора, рабочих агентов и критиков, обеспечивая распределение задач и проверку качества.  
6. Для продуктивного применения необходимы оценка (траекторный бенчмарк), наблюдаемость (трассировка), оптимизация стоимости/задержки (кеширование, стриминг, батчинг) и защитные меры (guardrails, sandboxing, HITL, аудит‑трейл).  

## Паттерны/фреймворки
- **ReAct pattern** — циклический процесс рассуждения, выполнения действия и наблюдения за результатом, лежащий в основе агентного поведения.  
- **LangChain/LangGraph** — Python‑фреймворки для построения агентных workflows в виде цепочек или ориентированных графов состояний.  
- **Model Context Protocol (MCP)** — открытый стандарт, обеспечивающий единый интерфейс подключения агентов к внешним инструментам и источникам данных.  
- **Retrieval‑Augmented Generation (RAG)** — техника обогащения промпта LLM релевантными фрагментами из внешней базы знаний для доступа к актуальной или приватной информации.  
- **Guardrails & sandboxing** — набор правил и изолированных сред, проверяющих ввод/вывод агента и предотвращающих вредоносные или небезопасные действия.  

## Применимо к нам
- Внедрить ReAct‑цикл с внутренним scratchpad‑ом в наши агенты, добавив чёткие условия остановки и логирование промежуточных мыслей.  
- Использовать LangGraph для оркестрации сложных пайплайнов: определить узлы как инструменты (API, БД, кодовые исполнители) и рёбра как переходы на основе наблюдений.  
- Подключить внешние сервисы через Model Context Protocol, чтобы агенты могли единообразно вызывать функции, выполнять запросы к поисковым движкам или внутренним репозиториям.  
- Применить RAG‑подход для актуализации знаний агентов: хранить документы в векторной базе и извлекать релевантные фрагменты перед каждым шагом рассуждения.  
- Добавить guardrails (фильтрация токсичного контента, проверка типов аргументов) и sandboxing (изолированные контейнеры/Docker) для безопасного выполнения сгенерированного кода или системных вызовов.  
- Организовать мультиагентную систему: оркестратор распределяет задачи, рабочие агенты выполняют конкретные действия (например, генерация кода, анализ данных), критики оценивают качество результатов и инициируют ретрай или корректировку.  
- Реализовать иерархическую память: рабочая — текущий контекст диалога, эпизодическая — история траекторий агентов, семантическая — долгосрочные факты из базы знаний, внешняя — кэшированные результаты инструментов.  
- Оценивать агентов траекторным бенчмарком (сравнение ожидаемой и фактической последовательности действий), обеспечивать наблюдаемость через OpenTelemetry‑трейсы, оптимизировать стоимость/задержку кешированием ответов LLM и батчингом запросов к инструментам.  

## Оценка ценности
**8/10** — материал даёт чёткую, структурированную картину построения агентных систем, охватывая теорию, практические паттерны и инфраструктурные аспекты (память, наблюдаемость, безопасность). Недостаток — ограниченная глубина по продвинутым темам (например, обучение с подкреплением для агентов) и отсутствие конкретных кейсов из production‑среды, что снижает применимость без дополнительного поиска источников. Тем не менее, для старта и выработки внутренних стандартов агентных пайплайнов руководство крайне полезно.
