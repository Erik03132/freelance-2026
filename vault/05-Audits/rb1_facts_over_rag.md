# RB-1: Память-факты vs сырая векторизация (сверка)

> Дата: 06.08.2026 · Источник: Habr 1065060 «Ио: 6 лет Telegram-бота»
> (факты с весами > сырые сообщения в RAG; describe-once для картинок).

## Сверка с нашим стеком

| Вывод «Ио» | Наш стек | Совпадение |
|---|---|---|
| RAG по сырым сообщениям почти бесполезен; полезны устойчивые ФАКТЫ | claude-mem: kind=decision/bugfix/session-summary (семантически структурированные наблюдения), не сырые логи | ✅ совпадает |
| Пайплайн фактов: извлечь → оценить важность → найти похожие → обновить/увеличить вес | claude-mem наблюдения с метаданными + релевантность (memory_context), memory compact (dedupe, keep 500) | ✅ совпадает (компакция = веса) |
| Ранжирование по дате+важности, топ-10 в контекст | memory_context: топ-N релевантных | ✅ совпадает |
| describe-once (картинку описать 1 раз, хранить описание) | НЕ внедрено для Angela/levitan (скрины bitrix-сканов пересылаются сырыми) | ⚠️ RB-2 (внедрить) |
| Self-hosted эмбеддинги (multilingual-e5-small) вместо внешних API | smart-rag использует sentence-transformers локально | ✅ совпадает (RB-3 = опция) |

## Решения
1. **RB-1: подтверждено** — архитектура claude-mem соответствует выводу статьи.
   Действий не требуется, фиксируем как валидацию.
2. **RB-2**: для bitrix-сканов (скриншоты сделок/звонков) добавить шаг «описать картинку
   1 раз → хранить описание» в pipeline сканера — экономия vision-токенов при повторных
   анализах (в очередь Levitan, задача LV-3 контекстно связана).
3. **RB-3**: self-hosted эмбеддинги уже основа smart-rag (sentence-transformers) —
   держать как есть, внешние API не используются.

## Статус
- RB-1 ✅ сверено (совпадение полное)
- RB-2 → в ACTIVE_TASKS как внедрение (связано с LV)
- RB-3 ✅ уже так
